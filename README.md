# SuperDoc repros

Four reproducible failures in `superdoc`, each on a bare mount (`main.js`: no extensions, no custom UI) with a small synthetic document. Every script drives real Chromium through Playwright and prints what `onException` received.

| # | Script | What happens | 2.25.0 | 2.29.0 |
|---|---|---|---|---|
| 1 | `npm run repro:selection` | Drag-selecting onto a tracked deletion of a field throws in the DOM worker | fails | fails |
| 2 | `npm run repro:undo` | Undo, redo, undo without waiting for each render throws; the page can keep showing undone text | fails | fails |
| 3 | `npm run repro:redo` | In suggesting mode on a long document: type, undo, redo (slowly) throws and the text is not restored | fails | fails |
| 4 | `npm run repro:diff` | `diff.compare()` rejects a snapshot from `diff.capture()` when one table has several tracked row deletions | fails | fails |

All four arrive as `worker-dom.failed` / `RENDER_ERROR` with `severity: "error"` (1 to 3), or as a rejected promise (4). After 1 to 3 the editor still accepts clicks, typing and export.

## Run

```bash
npm install
```

```bash
npx playwright install chromium
```

```bash
npm run repro
```

To try another version: `npm install superdoc@<version> --save-exact`, then run again. `npm run dev` serves the same page for trying each by hand (`?doc=deleted-field`, `long-document`, `deleted-rows`, `plain`; add `&mode=editing`).

The documents under `docs/` are generated by `scripts/make_fixtures.py` (standard library only), so the markup behind each one is readable there.

## 1. Drag-select onto a tracked deletion of a field

Document: `docs/deleted-field.docx`. One paragraph is a contents entry, a `HYPERLINK` field wrapping a `PAGEREF` field, deleted as a tracked change (`w:del` around the field characters, `w:delInstrText`, `w:delText`).

Steps: press on the plain first line, drag onto the struck-through entry, release.

```
worker-dom.failed: WorkerTransportError: Deleted pointer hit has no current canonical source owner
```

- Thrown on the first pointer move over the deleted entry. The rest of that drag no longer extends the selection.
- A plain click on the same text is fine. `documentMode: "viewing"` does not throw.
- On a real document we also saw `Pointer focus is unavailable in the displayed scene` and `Tracked pointer has no current canonical paragraph owner` from drags that start or end on tracked deletions.

## 2. Undo, redo, undo in quick succession

Document: `docs/long-document.docx` (900 plain paragraphs), `documentMode: "editing"`. Also fails on the five-paragraph `plain` document (`DOC=plain npm run repro:undo`).

Steps: click into a paragraph, type ten characters, then press undo, redo, undo, redo, undo, undo with no pause.

```
worker-dom.failed: Error: txId tx-…:undo was correlated with two render targets (8/1, 16/1)
```

- Control: `GAP_MS=700 npm run repro:undo` presses the same keys 700 ms apart and raises nothing.
- Six undos in a row with no pause are fine; the failure needs a change of direction.
- After the failure the page can still show the typed text although the document no longer contains it (the script prints this).

## 3. Redo of an undone tracked insertion on a long document

Document: `docs/long-document.docx`, `documentMode: "suggesting"`.

Steps: click into a paragraph, type ten characters, wait a second, undo, wait a second, redo.

```
worker-dom.failed: Error: Worker authored annotations have an unproved source transition
```

- The redone text is not painted.
- Controls: `MODE=editing npm run repro:redo` and `DOC=plain npm run repro:redo` (five paragraphs) both raise nothing.

## 4. `diff.compare()` on a table with tracked row deletions

Document: `docs/deleted-rows.docx`. One table, five rows, three of them deleted as tracked changes by the same author at the same time (`w:trPr/w:del`).

Steps: `const baseline = await doc.diff.capture()`, type one edit, `await doc.diff.compare({ targetSnapshot: baseline })`.

```
diff.compare: invalid full snapshot — payload.compareSnapshot.annotations[1].entries[10].key:
duplicate key "struct:main:/word/document.xml|row-deletion|Reviewer|2026-01-01T00:00:00Z|tbl:p:00000002"
within family "tracked-changes" (first declared at annotations[1].entries[9].key)
```

The key for a row deletion is built from author, date and the table, so every deleted row in one table gets the same key and the snapshot the engine produced fails its own validation.

## Environment

macOS (Apple silicon), Chromium via Playwright 1.64.0, Node 26. `superdoc` 2.25.0 and 2.29.0.
